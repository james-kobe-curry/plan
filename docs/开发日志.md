# plan 开发日志

整理日期：2026-09-16（2026-09-17 补充 GitHub 接入记录）。当前基线：**1.12.1 / versionCode 16**。

这份日志记录产品选择、实现演进和验证方法。历史部分根据现有验证文档、交付源码包及需求记录回溯；本次 GitHub 接入从当前工程建立版本管理基线，不用事后补造的提交冒充早期开发历史。逐版用户变化见 [版本更新日志](../CHANGELOG.md)。

## 一、产品方向与保留的约定

plan 面向手机上的学习计划，兼顾健身和日常任务，以 Android 安装包交付。使用流程是建立任务、按安排执行、确认实际进度，再从历史和复盘中查看积累。

在迭代中明确了以下约定：

- **任务默认轻量**：新任务只需名称，数量与时间目标选填；不把所有任务预设为若干分钟。
- **专注与完成分开**：计时结束记录专注时长，任务的实际完成情况仍由打卡确认。
- **记录长期保留**：归档只结束安排，历史、心得和专注仍可查看，也要进入相应备份。
- **心得完全选填**：任务心得和每天一篇的独立心得并存，不写心得也能正常打卡。
- **分享由用户操作**：用进度卡和 Android 系统分享面板表达阶段进度；不实现账号、实时好友状态或自动向他人发送内容。
- **外观可选且适度**：名称为 plan，保留原图标；默认柔和，同时提供清简、纸页及六种点缀色。主题需要改变实际排版风格，而不只改变颜色。
- **减少重复操作**：复制任务曾在 1.8.0 加入，1.9.0 移除；已创建的副本保留。更多精力用于数据可靠性和日常操作的一致性。

## 二、阶段记录

以下日期取自对应验证记录，用于定位验证批次，不作为独立发布日或 Git 提交时间。

### 2026-09-15：建立核心流程（1.0.0–1.1.0）

完成今日、计划、专注和记录四个入口，打通计划创建、打卡、历史、计时与备份。随后根据使用反馈，把打卡改成方框入口；修改单位后清空数量；时间类任务带入专注目标，并允许自定义时长。

这一阶段将应用从「同频」更名为 plan，保留应用标识和签名以支持覆盖升级。任务从默认时长目标转为只填名称即可建立，数量与长期目标成为可选项。七日图将星期和日期分开显示，增加大字体核对。到 1.1.0，规则测试增至 71 项，并实际验证后台专注通知和数据恢复。

### 2026-09-16：保存积累与处理提醒（1.2.0–1.5.0）

首先补全归档详情、分类备份和命名存档，解决“结束的任务也要能回顾”的需求。计划导入与记录导入分开，避免只补历史记录时增加每日待办。长表单的必填提示改为固定可见。

随后处理提示音问题：提供四种内置声音、自定义导入、试听和测试提醒；针对“试听有声、通知无声”的小米 14 反馈，加入兼容播放和诊断。用户确认 1.4.0 测试及锁屏结束均有声音。这个反馈只属于对应版本，不替代后续版本的真机复测。

备份从单份数据扩展为完整 ZIP，带入存档、音频和设置。继续增加自动存档、备份提醒、任务提醒与周月复盘。重点是让已有数据可找回，并把跳过、暂停与实际未完成区分开。到 1.5.0，自动测试为 253 项。

### 2026-09-16：提高连续使用体验（1.6.0–1.8.0）

打卡改为默认输入本次新增量，纠错时可直接修改当天总量。表单草稿按任务及日期隔离；保存结果不确定时不自动重复提交。计划修订保留旧版本，避免新目标改变过去记录。

首页加入换肤，专注支持常用时长管理，并区分上次手动选择与任务自动带入。进度卡支持范围、详细程度和隐私开关。对应备份格式逐步扩展，始终保留旧格式读取。到 1.8.0，自动测试为 383 项。

### 2026-09-16：个性化与简洁界面（1.9.0–1.11.0）

风格扩展为清简、纸页和柔和，同时加入资料、头像、自定义分类及首页布局。根据后续选择，将默认风格改为柔和，调整六种点缀色，缩小完成率圆环中的数字。

新增独立每日心得，首页能直接进入；保留任务心得，二者都选填。进度卡统一称为分享，默认每日、详细，心得默认隐藏。界面整理时统一按钮层级和至少 48dp 的主要点击区域，压缩装饰，保留大字体、软键盘和滚动位置适配。1.11.0 沿用 437 项逻辑测试，并通过模拟器核对实际布局。

### 2026-09-16：一致性与全面回归（1.12.0–1.12.1）

1.12.0 加入打卡、跳过及暂停后的快捷撤销，统一首页、计划与专注列表顺序，并明确过去日期的浏览状态。测试增至 473 项。

用户随后要求对现有全部功能和逻辑进行测试。本轮停止增加产品功能，按任务、历史、专注、个性化、备份和异常恢复划分检查范围，交叉核对页面显示与实际保存内容。发现并修复：

1. 计划导入只逐项处理冲突，可能拼出同一系列的重叠安排；改为按整个系列检查。
2. 合并导入从旧数据生成结果，可能覆盖恰好发生的另一笔更新；改为锁内读取、合并和保存。
3. 历史代表及日期生效规则不一致，可能使恢复后的任务显示为归档或统计重复；统一派生视图规则，保留原始记录。
4. 主数据损坏时已有 ZIP 和存档入口不足；补全恢复入口并保留损坏原件。
5. 专注偏好写失败后内存先发生变化，造成界面假成功；增加持久化结果检查、回退和重试。
6. 旧提示条可能遮挡新表单按钮；只在需要承接撤销的窗口继续显示。
7. 完整 lint 发现 Android 8.0 不支持的导航栏属性；改用对应 API 版本资源。

这些修复组成 1.12.1，共新增 38 项测试。最终 41 个套件、511 项全部通过；Debug 和 Release 完整静态检查无错误，各保留 46 条已审阅警告。已验证场景没有剩余阻断问题，进入稳定维护阶段。

## 三、当前实现结构

| 层次 | 实现与职责 |
| --- | --- |
| 界面 | Kotlin、Jetpack Compose、Material 3；入口与主导航位于 `MainActivity.kt`、`PlanApp.kt`，表单、历史、设置、分享等分别组织。 |
| 规则 | `Domain.kt`、`PlanStateRules.kt`、`HistoryQuery.kt`、`PeriodReview.kt` 等负责安排版本、日期、数量、状态及统计；尽量把可确定的计算留在纯规则层。 |
| 当前数据 | `AppStore.kt` 负责 JSON 的原子保存、锁内变更、恢复安全副本及读取异常保护。任务用 `seriesId` 关联历史安排版本。 |
| 表单输入 | `DraftStore.kt` 保存草稿；正式数据和草稿分开，草稿不计入统计或备份。`CheckInSubmission.kt` 核对提交基线，`QuickUndo.kt` 实现有冲突保护的局部撤销。 |
| 专注与提醒 | `FocusClock.kt`、`FocusPersistence.kt` 处理计时持久化，服务、闹钟与通知负责后台行为；完成记录与任务打卡分别保存。提醒诊断与兼容播放器提供故障定位。 |
| 数据迁移 | `TransferData.kt` 负责分类导入，存档模块保存阶段快照；完整 ZIP 模块校验清单、文件和偏好，并用恢复事务处理失败及中断。 |
| 外观与分享 | 风格、配色和首页偏好独立管理；进度卡先生成模型再绘图，经系统分享面板交由用户选择后续操作。 |

工具链以当前构建文件为准：JDK 17 或 21，Gradle 8.14.3，AGP 8.12.0，Kotlin 2.1.20，compile／target SDK 36，minSdk 26。内部目录和包名仍保留 `Tongpin` / `com.tongpin.app`，以维持现有安装及数据兼容，用户可见名称为 plan。

## 四、数据格式与升级原则

| 类型 | 当前格式 | 范围与兼容 |
| --- | --- | --- |
| 当前应用数据 | JSON v8 | 任务、归档、记录、每日心得、资料、分类；读取兼容 v1–v7。 |
| 分类传输 | `plan-transfer` v1，内部 JSON v8 | `.plan.json`；计划、记录、全部数据各有明确范围。计划／记录合并，全部数据替换恢复。 |
| 完整备份 | ZIP v5 | `.plan.zip`；另含命名及自动存档、提示音和应用偏好，读取兼容 v1–v4。 |
| 命名与自动存档 | 阶段数据快照 | 保留当时任务、归档及记录；不等同于完整应用设置备份。 |

应用版本、Android `versionCode` 与数据格式版本分别管理。发布新版本时递增应用版本及 `versionCode`；只有持久化结构需要改变时才升级格式，并说明缺省值、旧版读取和恢复规则。签名私钥须由维护者独立保管，不能进入 Git；正式覆盖升级继续使用原签名。

## 五、验证方法和当前边界

本轮执行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:lintRelease :app:assembleRelease
```

发布构建需要维护者的本机签名配置。可复用的规则测试位于 `app/src/test/java/com/tongpin/app`；详细执行结果见 [验证记录](验证记录.md) 和 [全面回归测试](全面回归测试-2026-09-16.md)。

验证分三层，记录时不互相替代：

- **规则与故障注入**：覆盖数量、日期、并发、去重、持久化失败、备份损坏和事务回滚等确定性条件。
- **Android 模拟器实操**：覆盖升级、表单、后台专注、文件选择器、音频导入、主题、备份和恢复；核对界面之外的实际 JSON、偏好及只写入一次的完成记录。
- **真机体验**：当前 1.12.1 尚未在小米 14 上复测。扬声器真实出声、厂商长期省电行为、所有 Android 版本和第三方分享接收应用不能据此视为通过。

当前 lint 仍有 46 条警告，包含 KTX 建议、同步偏好提交、动态加载音频资源及依赖／平台维护提示；同步提交在需要确认落盘结果的路径有意保留。未通过新增忽略配置把它们隐藏，也不把“0 错误”写成“0 警告”。

## 六、接入 GitHub 与后续维护

2026-09-17 将当前工程推送到 GitHub 仓库 https://github.com/james-kobe-curry/plan ，完成接入：

- `main` 分支以当前源码、测试、资源、文档、工具和验证截图建立**唯一基线提交**，不补造早期版本提交。
- 基线提交打附注标签 `v1.12.1`，指向真实的 1.12.1 发布源码。
- 加入 GitHub Actions 工作流 `.github/workflows/ci.yml`：推送、PR 和 `v*` 标签自动执行单元测试、Debug lint 和 Debug 构建。
- 安装包与源码包不进入 Git 历史：1.12.1 的 APK、源码包和校验值发布在 `v1.12.1` Release；1.0.0–1.12.0 的历史安装包与源码包集中发布在关联 `legacy-archives` 标签的“历史版本归档”Release。该标签只用于挂载资产，不代表对应版本的 Git 源码状态。
- 签名私钥、`local.properties`、构建缓存、日志和设备数据均未提交。
- 具体分支、提交、CI 与发布清单见 [开发与发布流程](开发与发布流程.md)。

既有本地 APK 和源码交付包用于核对历史，不能直接视为 Git 历史；历史版本条目不事后创建伪提交。

后续每次修改保持以下记录方式：

1. 从 `main` 切工作分支，独立提交说明触发条件、最终行为及验证结果，避免只写“优化”或“修复问题”，经 CI 全绿后合并。
2. 用户可感知的变化写入 `CHANGELOG.md`；产品取舍或重要存储／迁移决策写入本日志。
3. 发布时更新 `versionName`、递增 `versionCode`，保存对应验证记录；版本标签采用 `v版本号`，指向真实发布源码，并在 GitHub Releases 上传 APK、源码包与校验值。
4. 核对 APK 签名、图标、包名及覆盖升级数据，记录产物 SHA-256；构建缓存、签名私钥、本机路径、设备数据和测试备份不提交。
5. 后续优先处理实际反馈与真机兼容；调整依赖或平台 API 时安排相应回归，不为增加功能而打破现有数据和操作规则。

目前没有计划继续扩充功能。下一步以稳定使用反馈、真机提醒表现和常规维护为主。
